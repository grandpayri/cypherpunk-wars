ZK Spike: Bind Payload's Declared Yield to the Proof

Tests a new covenant check: the payload's declared provenYieldHex (32 bytes, appended after the existing 42-byte game-state body -- see encodeGameStateSnapshot's PROVEN_YIELD_BYTES trailer) must byte-for-byte equal the ZK proof's own public yieldAmount output, verified via OpTxPayloadSubstr (KIP-10, 0xb8) + OpEqual. Closes the gap where a modified client could write any yield/punkw value into the payload regardless of what the proof actually verified -- see design-bible.md's state-continuity notes and the session conversation that led here.

RUN_HONEST submits a transaction whose payload's provenYieldHex genuinely matches the proof -- expect SUCCESS. RUN_TAMPERED submits the SAME valid proof but a payload with a DIFFERENT declared yield -- expect REJECTION, proving the check actually constrains something.
