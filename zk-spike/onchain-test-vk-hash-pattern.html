ZK Spike: VK-Hash Pattern (Scalable Covenant Design)

Tests storing only a 32-byte OpBlake2b hash of the verifying key in the redeem script, instead of the full ~392-byte VK -- the full VK is supplied via the sig script at spend time and OpDup'd so one copy can be hash-checked while the other feeds OpZkPrecompile. Keeps per-action script growth constant (~40 bytes) instead of linear in VK size as more action types get added to the shared Gameplay Vault covenant. See the session conversation ("is this pattern scalable") for the full reasoning.

RUN_HONEST supplies the real VK matching the stored hash -- expect SUCCESS. RUN_TAMPERED supplies a DIFFERENT (but still validly-formatted) VK that doesn't match the stored hash -- expect REJECTION.
